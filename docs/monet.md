# 莫奈取色修复

位于“美化 → 修复莫奈取色”，默认关闭，仅需勾选系统界面 `com.android.systemui`。开启或关闭后重启 SystemUI；开启后可更换壁纸检查颜色是否更新。

## 实现范围

启用样本中保留的原生 `ThemeOverlayController`，沿用其壁纸颜色监听、调色板生成及 OMS 覆盖层流程。只覆盖 SystemUI 的 `bool/flag_monet`，并在控制器启动前修正已缓存的启用字段，不替换壁纸服务或伪造壁纸颜色。

作业帮部分控件使用固定颜色，因此同时将以下部分接入框架动态色：

| 控件 | 接入范围 |
| --- | --- |
| 快捷设置磁贴 | 选中背景、对应文字和图标的黑白对比色 |
| 亮度条 | 已完成进度 |
| 厂商密码界面 | 数字键按下背景、对应文字、已输入圆点 |

浅色使用 `android:color/system_accent1_600`，深色使用 `system_accent1_100`。系统发布新的资源配置后刷新已有视图，包括状态未变化的磁贴及其图标缓存。其他应用只有使用系统动态色资源时才会跟随，此功能不恢复整个 AOSP 下拉布局，也不替换所有固定颜色。

“自定义 SystemUI 主题色”同时开启时，上表控件优先采用手动颜色；原生 Monet 仍可更新系统调色板。关闭修复不会清除系统保存的主题设置或已生成覆盖层，因此系统此前生成的配色可能继续保留。

## 样本与验证

已核对 Google Drive 中 Android 12／14 的 SystemUI 样本：两版均保留原生控制器及壁纸监听逻辑。12 的 `flag_monet` 为 true，14 为 false；两版快捷设置选中背景均使用固定蓝色，配置变化时没有主动重算磁贴颜色。

运行 `python tests/check_systemui_theme.py`，主机检查覆盖资源归属、开关关闭回退、控制器启动、启动异常处理、浅深色取色、手动颜色优先级、磁贴及子类刷新、亮度与密码控件刷新、Drawable 复制和对比色。未编译 APK，真实设备的壁纸回调、OMS 权限及动画效果仍待验证。

缺失目标或原生更新失败时记录 `[Arashi-Monet]`；着色或刷新失败记录 `[Arashi-SystemUITheme]`。原生启动更新的运行时异常会被记录，避免该更新异常直接中断 SystemUI 启动。日志回退不代表设备已经成功生成动态配色。
