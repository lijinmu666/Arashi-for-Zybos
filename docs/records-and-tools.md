# 记录、通知与环境工具

## TCP 拦截与记录

“TCP 服务 → 屏蔽锁机广播”默认关闭，拦截 ZpTcpService 发出的 `login.fail` 广播。它只阻止本地广播分发，不改变服务器端设备封禁、账号或激活状态

记录保存可获取的时间、错误类型与错误码、来源、进程、PID、详情和调用栈，不把所有错误码都解释为同一种原因，也不保存登录令牌和设备密钥。列表支持详情动画、复制、分页、刷新及清空

成功拦截后可发送通知，点击进入 TCP 拦截记录页。没有成功拦截时不发送“已阻止”通知

## 卸载验证

黑白名单判断发起者的包名或 UID，黑名单优先于白名单。需要弹窗的请求在息屏时拒绝，已经显示的弹窗也会结束并返回拒绝；白名单放行与黑名单拒绝不受息屏规则影响

倒计时可选 5、10、15、30 秒，默认 10 秒，到期未响应默认拒绝。“伪装卸载结果”只改变拒绝请求的外部回调，不实际卸载目标，记录保留真实决定

两类记录均存放在 Arashi 自身的 SQLite 数据库中。清空按钮直接启动删除，先取消并等待旧读取结束，删除后读取第一页并显示数量；失败显示原因。清除后新发生的事件仍可新增记录，通知设置不负责停止记录写入

## 通知设置

入口：应用偏好设置 → 通知设置

| 开关 | 触发条件 |
| --- | --- |
| TCP 拦截 | 成功阻止 login.fail |
| 卸载黑名单 | 发起者命中黑名单，被拒绝 |
| 卸载白名单 | 发起者命中白名单，被放行 |
| 卸载超时 | 弹窗倒计时结束，被拒绝 |
| 设备息屏 | 需要弹窗的请求因息屏被拒绝 |

这些通知偏好默认开启，各自独立，实际发送还受系统通知权限控制。关闭通知不会关闭对应 Hook，也不会停止记录。息屏通知描述的是拒绝，不是放行

## 快捷指令

冻结指令使用 `pm disable`，不是 `pm disable-user`。ErrorActivity 指令只禁用已识别桌面的对应 Activity 组件，不冻结桌面全局。系统升级的启用指令使用 `pm enable com.zuoyebang.iot.zp.lib.ota.server`

## Zybos 环境控制

活动：`com.lijinmu.arashi.tools.ZybosEnvController`，读取或写入 `persist.sys.env_config`，需要 root

- 环境菜单：`PRODUCTION`、`TEST`、`MOCK`，当前样本未确认 `NONE`，不能据此添加不存在的环境
- 应用商店调试悬浮窗控制 `isShowDebugTools`，tips 开关控制 `isTips`
- 两个编辑开关每次新进入页面均从关闭开始，不从属性恢复开关状态；这不会自动把系统中的对应字段改为 false，只有应用写入才生效
- “读取当前配置”执行实时读取并用弹窗格式化 JSON，不以页面编辑状态代替系统属性
- “应用并写入”基于读取的 JSON 更新所选字段，保留其他配置，并读取核对结果
- “重置为默认”写入以下完整配置

```json
{"env":"PRODUCTION","isShowDebugTools":false,"isTips":false,"tcpServerConfigs":[]}
```

`tcpServerConfigs` 是按环境选择的 TCP 端点配置，包含 `env`、`host`、`port`。它不是整个后台的替换入口，空数组也不代表关闭 TCP。自定义服务器编辑功能已移除：完整配置容易超过系统属性长度上限，页面不再提供添加、编辑和删除端点入口。普通环境写入仍保留原配置中的该字段；“重置为默认”按上面的完整默认 JSON 清空它

环境变更可能影响登录、激活与服务连接，界面提示重启后生效。不要把“读取当前配置”与“应用并写入”混用；查看配置不会执行写入

## 应用选择器排序与筛选

后台保留白名单、卸载黑白名单默认按“已勾选 → 用户应用 → 系统应用”显示，同组按名称排序；卸载黑白名单中的未勾选 UID 放在应用后面，手动添加的已勾选项同样置顶。筛选移除“已选择”，原“全部”统一改为“默认”。黑白名单保留 UID 筛选；手动添加后回到默认列表，仍可搜索或取消选择。

系统特权工具的卸载选择器是单次操作，没有勾选项，继续按用户应用、已更新的系统应用排序，筛选菜单中的“全部”改为“默认”。仍过滤不能直接卸载的原始系统应用。
