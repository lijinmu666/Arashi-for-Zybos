# 作用域、兼容性与已知问题

应用最低支持 Android 12，当前包名为 `com.lijinmu.arashi`。目标是 AIBangOS 的已分析组件，不以 Android 大版本相同推断所有固件均兼容

## 主要作用域

| 功能 | 相关作用域 |
| --- | --- |
| 卸载验证、Shell 安装及系统服务限制处理 | 系统框架，具体按设置页面提示 |
| AOSP 电池、Wi-Fi 与蓝牙图标、通知快捷回复、录屏声音选项、状态栏日期、阻止默认浏览器重设 | 系统界面 `com.android.systemui` |
| 开发者选项、设置菜单注入、原版应用详情与通知设置 | 设置 `com.android.settings` |
| 桌面图标圆角 | 设备对应桌面 `com.android.launcher3` 或 `com.zuoyebang.iot.pad.launcher14` |
| 壁纸支持 | 系统框架与对应桌面 |
| 导航与下拉面板限制拦截 | 系统框架、系统界面、对应桌面 |
| 始终使用传统电源菜单 | 系统框架与系统界面 `com.android.systemui`，两者均需勾选 |
| TCP login.fail 拦截 | `com.zuoyebang.iot.zptcpservice` |

完整判定以 `HookScopes.java` 与页面实际提示为准。首次勾选或改变作用域后需重启对应进程；系统框架需重启设备。缺少作用域时保留已有开关值，但相关选项不可用

## 系统特权工具限制

检测属性 `ro.build.version.os`，按数字版本比较：`V7.10.0` 及以上禁用 Arashi 安装器和系统特权工具。不能以 Android 12/14 代替此系统版本判断，也不应把这个限制理解为所有安装 Hook 均不可用

## AOSP 电池、Wi-Fi 与蓝牙图标

三个开关均位于“美化”，默认关闭，只需系统界面作用域，启用后重启 SystemUI。实现、版本修复与验证范围见 [AOSP 图标说明](aosp-icons.md)。

## 原版应用详情与通知设置

位于“行为”，默认关闭，仅需设置作用域。Android 12 与 14 使用不同的厂商控制器、头部类和按钮状态方法，均接回保留的 SettingsLib 操作栏。保留现有其他设置项，未恢复被删掉的完整原版页面。两套样本的接口及主机分支检查通过，真机显示、操作结果和其他固件兼容性仍待验证。详见[应用详情说明](app-details.md)。

## 应用通知设置

与应用详情共用“行为”中的“原版应用详情与通知设置”开关，默认关闭，沿用原详情开关已有状态，作用域为设置。两版样本的通知实现分别适配：14 使用保留的原版 XML 与 Block 控制器，12 以原版头部和主开关替换厂商可见控件，调用原通知回调，保留已有渠道列表与原限制。44 保留设置内原来的宿主与完整启动参数，不再替换 Activity。主机检查通过，实际显示、通知开关与渠道操作仍待真机验证。详见[应用详情与通知说明](app-details.md)。

## 当前验证范围

- AOSP 蓝牙已连接图标：Android 12／14 样本选用同名厂商资源，主机检查通过，真机效果待验证

- 应用详情操作栏（内部版本 42）：用户确认由原生应用列表进入时生效，由设置侧栏“应用与存储”进入未生效；43 强制切换 Activity 后用户反馈应用详情立即闪退；44 已撤回入口替换，并将界面修改延后到控制器、视图就绪后，尚无设备堆栈，根因与设备效果仍待验证
- AOSP Wi-Fi 图标（内部版本 40）：Android 12、14 均已获用户反馈可用；此前 Android 12 未生效的反馈已由用户更正
- AOSP 电池图标：Android 14 已获用户确认生效；Android 12 完成样本适配，待单独实测确认

- Android 14 通知快捷回复：用户已确认正常输入和回复
- Android 12 通知快捷回复：样本静态核对与主机侧检查通过，待设备实测
- 桌面壁纸、图标及文件夹、最近任务：两套桌面的匹配目标见[桌面兼容说明](launcher-compatibility.md)，模拟测试不代表所有固件视觉效果已验证
- 壁纸支持：用户确认此前 Android 14 可用、Android 12 不可用；已按参考模块补充系统服务 isSetWallpaperAllowed(String) 入口，更新后需重启设备，Android 12 实机效果待验证，详见[桌面兼容说明](launcher-compatibility.md)
- 录屏音源菜单：用户反馈 Android 14 可用，Android 12 菜单可显示但实际功能异常；已按 Android 12 SystemUI 样本补充最终启动请求的音源校正、反优化及后端诊断，主机检查通过，实机效果待验证，详见[录屏说明](screen-recording.md)
- Android 12 动态壁纸设置：此前有失败反馈，壁纸服务补充不等于已全面修复，仍需单独验证
- TCP 与卸载记录清空：已改为直接删除、取消旧读取并重新加载，构建通过，实机效果待用户确认
- 非原作者签名的警告关闭后卡顿：用户已反馈，静态检查未发现持续校验或故意降速逻辑，原因尚未定位

## 日志与验证边界

传统电源菜单已核对两份 SystemUI 样本，并使用对应 AOSP 12／14 的 `GlobalActions` 原源码完成主机路由测试。SystemUI APK 不包含厂商系统框架，实际固件的框架类与传统菜单项目仍需实机验证；缺失预期框架目标时跳过并记录 `[Arashi-LegacyPower]` 日志，详见 [传统电源菜单](legacy-power-menu.md)。

SystemUI 自定义主题色按 Android 12／14 样本匹配快捷设置和厂商密码键盘；主机测试覆盖状态分支、资源归属、Drawable 复制和关闭回退，待设备验证。使用方式及具体着色范围见 [SystemUI 主题色](systemui-theme.md)。

主机侧检查覆盖方法匹配、参数与策略分支，不覆盖真实 SystemUI 动画、输入法、厂商 Binder 服务或设备 GPU 性能。缺失目标会记录日志，固件更新后需再次核对类名和方法

签名警告只在主界面全新启动时检查，从后台返回不重复检查。签名不同不等于功能被刻意限速，尚未确认的卡顿问题不作为安全机制的预期效果
